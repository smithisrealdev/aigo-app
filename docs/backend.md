## แอปเรียกอะไรแล้วบ้าง

- หน้าแชต (`src/app/chat.tsx`) ส่งบทสนทนาให้ `trip-chat` แล้วอ่านคำตอบแบบสตรีมผ่าน `src/lib/backend.ts` (header `apikey` = publishable key, `x-device-id` = เลขเครื่องโหมดผู้เยี่ยมชม)

  การ์ดใต้คำตอบ (`src/components/cards.tsx`): ที่เที่ยว ที่พัก ร้าน และตั๋ว เป็นการ์ดรูปเลื่อนแนวนอน เที่ยวบินและบริการ (เช่ารถ บัตรรถไฟ รถรับส่ง eSIM ประกัน) เป็นแถว
  กดแล้วเปิดเว็บ (`src/lib/links.ts` ใช้รหัสพาร์ตเนอร์ชุดเดียวกับเว็บ): เที่ยวบิน Aviasales พร้อม marker 692842, ที่พัก Booking.com ตามวันที่ (ลิงก์ค้นของ Agoda เด้งกลับหน้าแรก),
  ตั๋วและบัตรรถไฟ Klook ผ่านลิงก์ affiliate, ร้านและสถานที่ Google Maps, เช่ารถ Localrent, รถรับส่ง Kiwitaxi, eSIM Airalo, ประกัน EKTA
  ราคาบนการ์ดเป็นค่าประมาณของ AI: ขึ้นต้นด้วย ~ และมีป้าย "AiGo ประมาณ · ยังไม่มีราคาจริง" ทุกใบ (R15b) ท้ายรายการบอกว่าราคาอาจเปลี่ยนตอนจองและ AiGo ได้ค่าแนะนำ (R25c)
  รูปมาจาก `place-photos` (`src/lib/photos.ts` แคชในเครื่องอีกชั้น)
- ช่องและชิป "ถาม AiGo" ในหน้าแผน สถานที่ วันนี้ และหน้างาน (`src/lib/ask.ts`) เปิดแชตพร้อมคำถาม แนบแผนของทริปไปกับข้อความแรก (ไม่แสดงในฟอง) ให้ AI ตอบเรื่องทริปนั้นพร้อมการ์ด
  ช่อง "บอก AiGo" ในหน้าแผน (รวมปุ่ม + ระหว่างจุดแวะและปุ่มวางแผนวันที่ว่าง) แก้แผนของวันนั้นจริง (R13): เรียก `generate-itinerary` แบบทำต่อให้ได้วันเดียว
  พร้อมคำขอ แผนเดิมของวันนั้น และที่แวะของวันอื่น (ไม่นับเป็นทริปใหม่) แก้แล้วแจ้งพร้อมปุ่มเลิกทำ (RA6) ถ้าปิด "ให้ AiGo แก้แผนเอง" เป็นข้อเสนอให้กดรับ (RA9)
  ทดสอบ: "ขอร้านราเมนเพิ่ม" ได้ Aji no Sanpei เพิ่มในวันที่ 1 และเก็บที่เดิมไว้ ใช้เวลาราว 20 วินาที
- กดให้ AiGo จัดการหลังแชตสรุปทริปแล้ว หน้างานของ AiGo ส่งงานวางแผน (`job: 'start'`) ให้ `generate-itinerary` แล้วเซิร์ฟเวอร์วางจนครบทุกวันเอง
  ปิดแอปหรือพับแอปไว้ก็ไม่หยุด (ดู "งานวางแผนบนเซิร์ฟเวอร์" ด้านล่าง) ทริปเก็บเลขงานกับ token ไว้ ตัวเก็บทริปถามสถานะทุก 3 วินาทีระหว่างแอปอยู่บนจอ
  แล้วเติมวันใหม่ลงทริป (`withPlanState` ใน `src/lib/itinerary.ts`) หน้าแผนเปิดดูได้ระหว่างนั้น วันที่ยังไม่มาขึ้นว่า "AiGo กำลังวางแผนวันที่ N"
  หยุดและลองใหม่เรียก `job: 'stop'` / `job: 'resume'` ทำต่อจากวันที่ได้แล้ว สถานะของแผนในแอปมาจากคำตอบของเซิร์ฟเวอร์เสมอ (สั่งสำเร็จแล้วจึงถามสถานะมาใส่)
  งานที่เซิร์ฟเวอร์ตอบ 403 (เช่นลบบัญชีแล้ว แต่ทริปยังอยู่ในเครื่อง) จบเป็น "ไม่สำเร็จ" ไม่ถามซ้ำ
  ทริปเก็บในเครื่องเป็นรายการ (`src/lib/tripStore.tsx`, key `aigo.trips.v1`) ทริปแรกคือทริปที่เปิดอยู่ ทริปเก่ายังอยู่ (R33) ทุกแผนได้ id ใหม่ วางทริปเดิมซ้ำจึงได้อีกทริป ไม่ทับของเก่า
  แท็บทริปแสดงทริปอื่นและเช็กลิสต์ก่อนเดินทาง (R24) ลบทริปที่เปิดอยู่ได้ที่หน้าบัญชี กด "หยุดสร้างแผน" ได้ระหว่างรอ (R8a) วันที่ได้แล้วยังอยู่
  ราคาที่ AI ไม่ได้ให้มาแสดงว่า "ยังไม่มีราคา" ไม่ใช่ "ฟรี" (R15c) ตั๋วสรุปบอกว่า AiGo เข้าใจแล้วกี่ข้อจาก 6 (R7)
  รูปของจุดแวะ ปกทริป และหน้าสถานที่ค้นจากชื่อผ่าน `place-photos` ราคาเป็นค่าประมาณของ AI และยังไม่ได้ตรวจเวลาเปิด (แอปบอกตรงๆ) ผู้เยี่ยมชมสร้างได้สัปดาห์ละ 1 ทริป (โควตาใน `guest_sessions`)
  เที่ยวบิน ที่พัก ร้าน และบริการที่ AI หาไว้ในแชต ส่งต่อมาเป็นงานที่เสร็จในหน้างาน และเก็บไว้ในทริป (`bookings`) แสดงท้ายหน้าแผน
- หน้าแรกและแท็บทริปแสดงทริปของผู้ใช้เท่านั้น ยังไม่มีทริปแท็บทริปชวนเริ่มวางแผน และมีลิงก์ "ดูตัวอย่างก่อนได้" (แผนโอซาก้า วันนี้ เที่ยวบินดีเลย์ ทริปที่เพื่อนแชร์) ซึ่งหายไปเมื่อมีทริปจริง
- หน้าวันนี้ของทริปจริงหาวันตามวันที่ในเครื่อง: ระหว่างเที่ยวบอกที่ถัดไปกับปุ่มนำทาง ก่อนเที่ยวบอกว่าอีกกี่วันและแสดงวันแรก
- แชร์ทริปจริงส่งเป็นข้อความแผนรายวันผ่านแอปไหนก็ได้ เพราะลิงก์แชร์ต้องบันทึกทริปขึ้น backend ก่อน (`get-shared-trip`)
- เข้าสู่ระบบและการซื้อบอกตรงๆ ว่ายังไม่เปิดในรุ่นทดลอง (เดิมปุ่มเข้าสู่ระบบแค่ตั้งค่าในเครื่องว่าเข้าแล้ว) หน้าแพ็กทริปไม่มีราคาช่องว่างแล้ว ใช้คำว่า "เร็วๆ นี้"
- ยังเป็นข้อมูลตัวอย่าง (เข้าได้จากลิงก์ตัวอย่างเท่านั้น): เที่ยวบินและที่พักที่รออนุมัติ (ต้อง deploy `search-flights` / `search-hotels`) และเที่ยวบินดีเลย์

  ปิดการคิดก่อนตอบ (reasoning) ของ Haiku เพราะทำให้คำแรกช้าราว 15 วินาที และกิน max_tokens จนคำตอบถูกตัดก่อนถึง [TRIP_SUMMARY]
  ท้าย prompt มี DIRECTIVE 12 สำหรับแอป: ตอบสั้นราว 80 คำ ไม่มีรูปและตาราง ข้อเสนอเป็นบรรทัดละวัน ตามด้วย [READY_TO_GENERATE] และ [TRIP_SUMMARY]
  เมื่อรู้ที่หมายแล้วทุกคำตอบมีการ์ด `[PLACE]` `[FLIGHT]` `[HOTEL]` `[RESTAURANT]` `[TICKET]` `[SERVICE]` แบบ `key: value | key: value` ชื่อเป็นภาษาอังกฤษ
  ถามไม่เกิน 2 ข้อทั้งแชต เลือกวันที่เองเมื่อผู้ใช้บอกแค่เดือน กฎการ์ดย้ำอีกครั้งในส่วนท้าย system ที่ไม่ได้แคช เพราะ Haiku มักลืมกฎที่อยู่ท้าย prompt ยาว
