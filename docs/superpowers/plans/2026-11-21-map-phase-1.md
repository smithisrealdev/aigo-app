# Map phase 1 (Mapbox) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real Mapbox map with numbered pins in plan order, a dashed line between stops and the traveller's position, on the map, plan and today screens.

**Architecture:** A pure `dayPoints` turns a day's places into pins (plan-order numbers, AI-guessed positions marked approximate, missing or far-away places left off). `TripMap` has a native file (Mapbox via `@rnmapbox/maps`, only when the native module and `EXPO_PUBLIC_MAPBOX_TOKEN` exist) and a web/fallback file (the existing `SketchMap`).

**Tech Stack:** Expo SDK 58, `@rnmapbox/maps` 10.3.18 (Mapbox Maps SDK v11, Standard style), React Native.

**Spec:** `docs/superpowers/specs/2026-11-21-in-app-map-design.md` (phase 1). Wikipedia coordinates (verified pins) are task 4, after the map works.

## Global Constraints

- No token, web, Expo Go or a failed map load: show `SketchMap`, never a broken screen.
- Pins numbered by plan order; the selected pin larger and another colour (R12); Mapbox/OpenStreetMap credit visible.
- AI-guessed positions: hollow dashed pin and "ตำแหน่งโดยประมาณ" on the stop; no position or more than 50 km from the day's other stops: no pin, "ยังไม่มีตำแหน่ง" and a Google Maps search button.
- Location only "when in use"; the Navigate button keeps opening Apple/Google Maps.

## Review Focus

- A day where every stop lacks a position: no map crash, the fallback shows, stops say "ยังไม่มีตำแหน่ง".
- A day with one stop: the camera centres on it instead of fitting bounds of a single point.
- Dark mode: Standard style night preset.
- Selecting a stop card moves the selected pin; tapping a pin selects the card.
- Web build bundles without `@rnmapbox/maps`.
