# Map look Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Day maps open with a fly-in from the globe, use AiGo colors, show place labels on the full-screen map, and turn travel days into a flight line to the next day's first stop.

**Architecture:** Pure geometry (travel day, great-circle line, plane spot, globe zoom) lives in `src/lib/mapPoints.ts` with node tests. `TripMap` (`src/components/tripMap.native.tsx`) gains three optional props (`intro`, `pois`, `travel`) and the Standard style colors. A small hook in `src/lib/globe.ts` builds the travel leg with the destination photo for the three screens that show day maps.

**Tech Stack:** Expo SDK 58, `@rnmapbox/maps` 10.3.18 (Mapbox v11 Standard style), react-native-reanimated (`useReducedMotion`), node test runner.

**Spec:** `docs/superpowers/specs/2026-11-21-map-look-design.md` (and phase 1 of `docs/superpowers/specs/2026-11-21-in-app-map-design.md`)

## Global Constraints

- No new dependencies; only Mapbox Standard style config (`StyleImport` `basemap`).
- Colors exactly as the spec: light `lightPreset: 'day'`, land `#F6EFE6`, water `#D4ECFF`, greenspaces `#D2F3E4`, roads `#FFFFFF`, motorways `#FFE9A8`, buildings `#EDE4D8`; dark `lightPreset: 'night'`, land `#1F1B17`, water `#22344A`, greenspaces `#1F3A30`, roads `#3D362E`, motorways `#3D3420`, buildings `#2A241F`.
- Fly-in about 2.5 s, once per screen open, only the plan header and the full-screen map; never on a day switch; skipped when the phone's Reduce Motion is on.
- Place labels (`showPointOfInterestLabels`) only on the full-screen map; small maps keep them off.
- Travel day = the day's last pin and the next day's first pin (both by `dayPoints` rules) more than 300 km apart; the last day of a trip is never a travel day.
- Travel line in the app's primary color, dashed, following the globe's surface, plane icon on it; arrival = the next day's first stop as a round photo with a primary ring, numbered pin 1 when it has no photo; camera ends at the arrival region (zoom 7).
- Mapbox logo and attribution stay visible (R12). The web keeps the drawn map.
- Commits end with the session's two attribution lines; push to `claude/awesome-cori-zvsu1f` and `main`.

## Review Focus

1. A flight that crosses the date line (Bangkok to Vancouver) must draw across the Pacific, not around the world — Task 1 `arc` continuity test.
2. A travel day whose next day has no positions yet (plan still being made) stays a normal map — Task 1 `travelLeg` test.
3. Reduce Motion on: the map opens straight at the day, no fly-in — reviewer reads Task 2 code (native, no unit test).
4. Switching days after the fly-in eases (600 ms), never replays the fly-in — reviewer reads Task 2 code.
5. A day trip to a nearby city (Osaka to Kyoto, about 45 km) is not a travel day — Task 1 `travelLeg` test.

**Interfaces:**
- Produces: `TRAVEL_KM = 300`; `type TravelLeg = { from: MapPoint; to: MapPoint }`;
  `travelLeg<P extends { id: string; lat: number; lon: number }>(days: P[][], day: number, label: (p: P) => string, checked: (p: P) => { lat: number; lon: number } | undefined): TravelLeg | undefined` (from = last pin of `day`, to = first pin of `day + 1`, both from `dayPoints`);
  `arc(a: { lat: number; lon: number }, b: { lat: number; lon: number }, n = 64): [number, number][]` (`[lon, lat]`, n+1 great-circle points, longitudes unwrapped so neighbours differ by under 180);
  `planeAt(line: [number, number][]): { at: [number, number]; rotate: number }` (the point about 80 km before the end, the middle point when the line is under 400 km; `rotate` = degrees to turn a north-east pointing icon to the direction of travel on a flat map);
  `globeZoom(w: number, h: number, pad: TripMapProps['pad'], lat: number): number` (the formula now inside `TripGlobe`).
