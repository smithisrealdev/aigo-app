# แผนที่จริงในแอปและการเดินทางระหว่างจุด (Mapbox) — design

วันที่ 21 พ.ย. 2026 · สถานะ: รอเจ้าของอนุมัติ

## ทำไม

เจ้าของอยากได้แผนที่สวยในแอปแบบ Strava และอยากให้ "seamless ที่สุด" คือผู้ใช้ไม่ต้องสลับไปแอปอื่นระหว่างเที่ยว
ตอนนี้แอปมีแค่ภาพแผนที่นิ่ง (ทริปตัวอย่าง) กับแผนที่วาด `SketchMap` (ทริปที่ AI สร้าง) ส่วนปุ่ม "นำทาง" ส่งต่อไป Apple/Google Maps (`navLink`, R16)
สเปก R12 เขียนไว้แล้วว่าต้องเป็นแผนที่จริง หมุดมีเลขตามลำดับ หมุดที่เลือกใหญ่กว่าและสีต่าง และแสดงเครดิตแผนที่

## เป้าหมาย

1. แผนที่จริงที่สวยและเป็นสไตล์ AiGo บน iPhone และ Android ในหน้าแผนรายวัน (`src/app/map.tsx`) หัวหน้าแผน (`src/app/itinerary.tsx`) และ "วันนี้" (`src/app/today.tsx`)
2. เห็นทั้งวันในหน้าเดียว: หมุดเลขตามลำดับ เส้นเชื่อมตามลำดับ แตะหมุดแล้วการ์ดของจุดนั้นขึ้น (R12)
3. ไปจุดถัดไปได้โดยไม่ต้องออกจากแอปในกรณีส่วนใหญ่: เส้นทางเดินจริง ขั้นตอนนั่งรถไฟ และตำแหน่งของเรา
4. ใช้ได้ตอนไม่มีเน็ต (เฟส 3)

## ไม่ทำ

- เสียงนำทางทีละแยกในแอป และเวลารถออกแบบสด (ยังมีปุ่มเปิด Google/Apple Maps ไว้สำหรับเรื่องนี้)
- กราฟความชัน heatmap segment แบบ Strava
- แผนที่ Mapbox บนเว็บ: เว็บใช้ `SketchMap` เหมือนเดิม (rnmapbox บนเว็บต้องใช้ webpack แต่โปรเจกต์ใช้ Metro)

## ห้ามเกิด (ถึงทำงานได้ก็ถือว่าพลาด)

- หมุดผิดที่บนแผนที่จริง เช่น ตกทะเลหรืออยู่คนละฝั่งเมือง (พิกัดตอนนี้มาจาก AI เดาเอง)
- ขั้นตอนรถไฟที่พาหลง เช่น บอกสายที่ไม่จอดสถานีนั้น
- ข้อมูลที่ AI เขียนแสดงเหมือนข้อเท็จจริงที่ตรวจแล้ว

## ข้อจำกัด

- Mapbox เป็น native module ใช้ใน Expo Go ไม่ได้ ต้อง build แอปเอง (เจ้าของ build ลง iPhone จาก Mac ได้แล้ว ตาม `docs/iphone-build.md`)
- ต้องมีบัญชี Mapbox และ public token (`pk.`) ใส่ในแอปผ่าน `EXPO_PUBLIC_MAPBOX_TOKEN` (ไฟล์ `.env` บน Mac ของเจ้าของ) ไม่มี token ให้ใช้ `SketchMap` แทน
- ข้อมูลเส้นทางของ Google ใช้บนแผนที่ที่ไม่ใช่ Google ไม่ได้ (เงื่อนไขของ Google) ขั้นตอนรถไฟจึงมาจาก AI
- ผลจาก Mapbox Directions ต้องแสดงบนแผนที่ Mapbox ซึ่งตรงกับที่ใช้อยู่แล้ว และต้องแสดงเครดิต Mapbox/OpenStreetMap (R12)
- Mapbox คิดเงินตามผู้ใช้ต่อเดือนและมีโควตาฟรี ต้องเช็กหน้าราคาก่อนเปิดให้คนใช้จริง แอปยังไม่ปล่อยให้คนทั่วไป
- ขอสิทธิ์ตำแหน่งเฉพาะตอนเปิดแอป (when in use) ไม่ติดตามตอนพับแอป

## แนวทางที่พิจารณา

| แนวทาง | ข้อดี | ข้อเสีย | ผล |
|---|---|---|---|
| A. Google Maps ในแอป + Routes API | ขั้นตอนรถไฟแม่นที่สุด | แต่งสีได้น้อยกว่า ไม่มีออฟไลน์ iPhone ต้อง build เอง | ไม่เลือก |
| B. MapLibre + แผนที่โอเพนซอร์ส | ฟรี ปรับได้ทุกอย่าง | ไม่มีข้อมูลรถไฟ ต้องทำเองหลายส่วน | ไม่เลือก |
| C. Mapbox + ขั้นตอนรถไฟที่ AI เขียน | สวย (Strava ใช้) มีเส้นทางเดิน มีออฟไลน์ | ขั้นตอนรถไฟต้องมีตัวกันผิด | **เจ้าของเลือก (21 พ.ย. 2026)** |

ผลทดลองก่อนตัดสินใจ (`docs/spikes/2026-11-21-ai-transit-steps.md`): Gemini 3.8 Flash เขียนเส้นทางรถไฟถูก 10/11, Claude Sonnet 5.5 ถูก 9/11, Claude Haiku 5.5 ถูก 4/11 จุดที่พลาดบ่อยคือจำนวนสถานีและเลขทางออก

## การออกแบบ

แบ่งเป็น 3 เฟส ทำและส่งให้ลองทีละเฟส แต่ละเฟสมีแผนงานของตัวเอง

### เฟส 1: แผนที่จริง

- ติดตั้ง `@rnmapbox/maps` (config plugin) และ `expo-location` (ข้อความขอสิทธิ์ภาษาไทย: "ใช้ตำแหน่งเพื่อแสดงว่าคุณอยู่ตรงไหนบนแผนที่ทริป")
- คอมโพเนนต์แผนที่ตัวเดียวใช้ทุกหน้า: รับรายการจุด (ตำแหน่ง เลขลำดับ ชื่อ) จุดที่เลือก และขอบที่ต้องเว้นให้แผ่นข้อมูลด้านล่าง
  - สไตล์: Mapbox Standard โหมดกลางวัน ลดป้ายร้านค้าที่ไม่เกี่ยว และใช้โหมดกลางคืนเมื่อแอปอยู่ในธีมมืด ส่วนหมุดและเส้นใช้สีแบรนด์ (`#4B5BEF`)
  - หมุดวงกลมมีเลขตามลำดับในแผน หมุดที่เลือกใหญ่กว่าและสีต่าง (R12)
  - เส้นประเชื่อมจุดตามลำดับ (เส้นตรงในเฟสนี้)
  - จุดตำแหน่งของเรา (ถ้าผู้ใช้อนุญาต) และปุ่มกลับมาที่ตำแหน่งเรา
  - กล้องซูมให้เห็นทุกจุดของวันนั้นพอดี โดยเว้นพื้นที่ให้แผ่นข้อมูลด้านล่าง
  - แสดงเครดิต Mapbox/OpenStreetMap ตามเงื่อนไข
  - ไม่มี token, อยู่บนเว็บ หรือโหลดแผนที่ไม่ขึ้น ให้ใช้ `SketchMap` แทน หน้าไม่พัง
- `map.tsx`: แผนที่เต็มจอ แผ่นข้อมูลด้านล่างลากขึ้นลงได้ เป็นรายการจุดของวัน มีชิปเลือกวัน และแตะหมุดกับแตะการ์ดแล้วไฮไลต์ตรงกัน
- `itinerary.tsx`: แผนที่หัวหน้าแสดงวันที่เลือก แทน `SketchMap`
- `today.tsx`: แผนที่เล็กแสดงจุดถัดไปกับตำแหน่งเรา
- ปุ่ม "นำทาง" ยังเปิด Google/Apple Maps เหมือนเดิมในเฟสนี้
- **ตำแหน่งหมุดให้ตรง** (กันหมุดผิดที่):
  - `place-photos` หาบทความ Wikipedia ของสถานที่อยู่แล้ว ให้ส่งพิกัดของบทความกลับมาด้วย และเก็บไว้ในตาราง `place_photos`
  - แอปใช้พิกัดจาก Wikipedia แทนพิกัดของ AI เมื่อสองค่าห่างกันไม่เกิน 5 กม. ถ้าห่างกว่านั้นถือว่าเป็นคนละที่ ให้ใช้พิกัดเดิม
  - จุดที่ไม่มีพิกัด (0,0 หรือไม่มีค่า) ไม่ปักหมุด และรายการบอกว่า "ยังไม่มีตำแหน่ง"
  - จุดที่ห่างจากจุดอื่นของวันเดียวกันเกิน 50 กม. ไม่ปักหมุด และให้ตรวจก่อน

### เฟส 2: เดินทางระหว่างจุดในแอป

- ช่วงเดิน (leg mode `walk`): ขอเส้นทางเดินจาก Mapbox Directions แล้ววาดตามถนนจริง พร้อมระยะและเวลา เก็บไว้ในทริป ไม่ขอซ้ำ
- ช่วงรถไฟหรือรถเมล์ (leg mode `train`): edge function ใหม่ `transit-steps` ใช้ Gemini 3.8 Flash กับ prompt จากผลทดลอง ขอทีละวันตอนผู้ใช้เปิดดูวันนั้นครั้งแรก แล้วเก็บไว้ในทริป
  - แสดงสาย ไปทางไหน ขึ้นและลงที่สถานีไหน และเวลาโดยประมาณ
  - ไม่แสดงจำนวนสถานีและเลขทางออก จนกว่าจะมีข้อมูลตรวจในเฟส 3
  - ติดป้าย "AI เขียน เช็กป้ายที่สถานีอีกที"
  - มีปุ่ม "ดูเวลารถจริง" เปิด Google Maps โหมดขนส่งสาธารณะ
  - ช่วงนั่งรถเป็นเส้นประจากสถานีขึ้นถึงสถานีลง เมื่อหาตำแหน่งสถานีได้ ถ้าหาไม่ได้แสดงเป็นข้อความอย่างเดียว
- ช่วงรถยนต์หรือแท็กซี่: ใช้เส้นทางขับรถจาก Mapbox
- "จุดถัดไป": บอกระยะและเวลาจากตำแหน่งเรา ถ้าเข้าใกล้จุดในระยะ 80 ม. ระหว่างเปิดแอป ให้ถือว่าถึงแล้วและเลื่อนไปจุดถัดไปเอง
- `navLink` เปิด Google/Apple Maps ตามโหมดของช่วงนั้น (เดิน รถไฟ ขับรถ) และเปิด Naver Map ในเกาหลี กับ Amap ในจีน

### เฟส 3: ออฟไลน์และตรวจข้อมูลรถไฟ

- ดาวน์โหลดแผนที่ของเมืองในทริปเก็บไว้ใช้ตอนไม่มีเน็ต (Mapbox offline) เมื่อผู้ใช้กดหรือก่อนวันเดินทาง และบอกขนาดก่อนโหลด
- นำเข้าข้อมูลสถานีและสายรถไฟจาก OpenStreetMap ของประเทศที่รองรับไว้ใน Supabase แล้วใช้ตรวจขั้นตอนที่ AI เขียน ผ่านแล้วจึงแสดงจำนวนสถานีและเลขทางออก
- การวางแผนทั้งทริปบนเซิร์ฟเวอร์ ให้เดินต่อแม้ปิดแอป เป็นงานแยกอีกชิ้น

## ที่เจ้าของตัดสินแล้ว

- ใช้ Mapbox และให้ AI เขียนขั้นตอนรถไฟโดยมีตัวกันผิด (21 พ.ย. 2026)
- แผนที่จริงอยู่บน iPhone และ Android บนเว็บใช้แผนที่วาดต่อไป
- ปุ่มเปิด Google/Apple Maps ยังอยู่เป็นทางสำรอง

## ที่ผมตัดสินเอง (เจ้าของแก้ได้)

- เริ่มจาก Mapbox Standard แล้วปรับสี ยังไม่ออกแบบสไตล์ใน Mapbox Studio เพราะเร็วกว่าและปรับทีหลังได้
- เฟส 1 ใช้เส้นตรงเชื่อมจุด เส้นตามถนนจริงรอเฟส 2 ที่มีข้อมูลเส้นทาง
- พิกัดจาก Wikipedia ใช้แก้หมุดผิดที่ เพราะเก็บไว้ได้และไม่มีค่าใช้จ่าย (ผลค้นหาของ Mapbox แบบทั่วไปห้ามเก็บ)
- ใช้ Gemini 3.8 Flash เขียนขั้นตอนรถไฟ จากผลทดลอง และค่าใช้จ่ายราว $0.005 ต่อช่วง

## ที่ปล่อยให้ผู้สร้างเลือก

- โครงสร้างคอมโพเนนต์ วิธีวาดหมุด (SymbolLayer หรือ MarkerView) และวิธีทำแผ่นข้อมูลด้านล่าง (ใช้ของที่มีในแอปก่อน ไม่เพิ่ม dependency ถ้าไม่จำเป็น)
- รูปแบบข้อมูลที่เก็บในทริปสำหรับเส้นทางและขั้นตอน
- เวอร์ชันของ Mapbox SDK ที่เข้ากับ Expo SDK 58
